# Planbox 下一阶段优化方案（讨论稿）

日期：2026-10-16。状态：产品方案草案，尚未实施，不替代现有 PRD 的历史记录。

## 1. 已确认的需求

- 输入：用户主动提供的微信公众号链接、小红书链接或图片，也保留粘贴正文作为补全方式。
- 处理：提取其中的活动、比赛及参与要求，结合个人情况筛选并排序。
- 排序目标：**每次收集时由用户选择目标**，不能把求职、学习等历史偏好固定成所有机会的排序规则。
- 规划：用户希望得到安排到具体时间段的可执行计划。
- 当前习惯：用户使用纸质小笔记本，没有固定使用数字日历。

因此首版规划采用 Planbox 内部时间表：用户录入已有安排和可用时间，系统生成计划，用户确认后执行或抄回笔记本。外部日历连接属于后续可选集成。

## 2. 产品目标和最小闭环

产品定位：**把用户收集的活动与比赛，转成与当前目标匹配、在已知时间条件下可安排的行动计划。**

最小闭环：

```text
选择本次目标 + 粘贴链接/上传图片
  → 获取正文与图片
  → 拆出一个或多个活动候选，保留字段证据
  → 用户确认关键事实或补充未知信息
  → 判断参与条件与个人约束
  → 在目标内排序，解释取舍
  → 用户选定候选活动
  → 拆分准备任务，估计投入并检查剩余容量
  → 排到可用时段，呈现冲突和未排任务
  → 用户确认计划
  → 完成、延期或放弃反馈，生成下一版建议
```

第一阶段聚焦活动、比赛及其准备任务。泛资讯和学习资料可先作为关联参考保存；不直接把所有信息转换成有截止日期的活动。

## 3. 采集与可信抽取

| 入口 | 处理方式 | 失败或不确定时 |
| --- | --- | --- |
| 微信公众号链接 | 修复当前 URL 校验，尝试读取正文及活动相关配图 | 保留来源链接，引导粘贴正文或上传截图 |
| 小红书链接 | 使用独立只读适配器解析用户提供的完整链接、正文与配图 | 登录态、链接参数或访问失败时转正文/截图补全 |
| 图片 | 多模态识别活动字段及对应文字区域；二维码作为独立待核验信息 | 模糊日期、看不清的二维码、年份缺失均待确认 |
| 粘贴正文 | 直接进入同一抽取流程 | 标记缺失字段，不用猜测填满表单 |

目标是三类入口共用同一后续流程；不承诺每条第三方链接都能读取。链接页面能打开，也不代表图片中的赛程与报名信息已经提取。

一篇文章或一张长图可以有多个活动；同一活动的多个来源需归并，日期或资格冲突需展示给用户。不存在活动的内容允许返回“未发现活动”，不能为完成任务强行生成卡片。

关键字段分为：

- **参与事实**：名称、主办方、活动类型、地点、线上/线下、费用、报名方式、参赛资格、组队要求、交付物。
- **固定节点**：报名截止、组队截止、材料提交、初赛、决赛、活动开始/结束。
- **证据与未知**：原文片段或图片位置、来源、获取时间、时间转换依据、冲突、缺失字段。

模型推测的工作量、收益、难度不能伪装成主办方要求。没有年份、时区或具体时刻时，保存不确定性；全天日期和精确时刻分别表示。

Review 必须可编辑关键字段并记录人工更正。事实字段确认和“选择参加”是不同动作。未确认的资格、关键截止时间不能被当作可靠排期依据。

## 4. 目标与个性化筛选

### 4.1 目标分开管理

收集时选择已有目标或新建目标，例如“形成可展示作品”“学习某项技术”“认识行业同伴”“争取比赛奖励”。这些只是示例，不是已确认的个人目标。

同一活动可关联多个目标，在每个目标下获得不同评估。切换目标可重新排序。不同目标的分数不能直接当作同一尺度；总览先按目标分组，跨目标计划需要用户指定优先顺序和时间分配。

### 4.2 个人情况最少需要什么

尽量用简短、可随时修改的设置：

- 希望从该目标获得的具体成果。
- 已有能力、经验和可用项目；用户未提供的部分保持未知。
- 地点、线上/线下、预算、是否能组队等约束。
- 每周可投入时段、已有固定安排、连续专注时长与缓冲偏好。

个人介绍或项目经历仅作为用户确认的背景，不能由模型补写为已掌握技能或正式经验。

### 4.3 先判断可参加，再比较值得程度

第一层判断资格、费用、时间、地点与组队等硬约束，输出“可考虑 / 条件待确认 / 已知不满足”。未知条件不等于不符合资格。

第二层在同一目标内比较：目标相关性、预期可形成的成果、当前能力与准备差距、投入成本、信息完整度。截止紧迫度独立显示，不能因为马上截止就自动认定更值得参加。

首版使用清楚的规则与模型解释，不将模型自报分数当成概率。每个推荐应包含：

```text
为什么适合当前目标
主要投入与准备差距（估计）
哪些条件已经确认，哪些还不知道
相对于其他候选的取舍
建议的下一步
```

排序允许用户调整；“不感兴趣”“时间太多”“已有类似经验”等反馈供后续评估使用，不直接把一次选择永久变成偏好。

## 5. 根据纸质安排生成时间表

### 5.1 忙闲信息从哪里来

用户先在 Planbox 录入笔记本里已有的固定安排，以及愿意投入活动的时段。可以只填“周三晚不可用”，无须录入私人事项细节。

拍摄笔记本并识别日程可以作为后续便利功能；首版不依赖手写识别。系统只能基于已录入的时间约束规划，不能声称知道未输入的安排。

### 5.2 规划包含两类时间

- **主办方固定时间**：比赛截止、线上会议、线下活动、答辩等，只能按事实记录，不能自由挪动。
- **用户准备任务**：核对规则、找队友、完成报名、准备作品、制作材料、演练、提交等，可在约束内安排。

每项准备任务保存预计耗时、估计依据、依赖关系、最晚完成时间和可否拆分。耗时由模型提出草案、用户修正；未知的重大工作量不得默认低成本。

### 5.3 排期规则

模型负责提出任务、收益解释和耗时估计；确定性的排期逻辑负责检查：

- 任务是否在允许的可用时段内。
- 是否与固定安排、其他计划时间块冲突。
- 前置任务是否先完成，提交是否早于真实截止。
- 总投入、连续工作时长、缓冲是否满足用户设置。
- 多个活动各自值得参加时，合在一起是否仍可安排。

规划前应评估截止前的总工作量与可用容量，再展开展示本周的具体时段。长期比赛超出已知可用时间范围时，只给有条件的阶段计划，明确哪些后续容量尚未确认。

排不下时展示未排任务、冲突及可选取舍，例如减少所选活动、调整可用时段或缩小自定作品范围。不得暗改主办方截止、占用未授权时段或删除已有安排来制造“排好了”的结果。

用户确认后形成计划版本。后续新增活动、延期或完成任务时，先生成调整建议，保留旧计划；已锁定时段和已有安排不被静默覆盖。

### 5.4 展示方式

“本周计划”先提供按天的清单和时间块，适合照着执行与抄回笔记本：

```text
周二 19:30—20:00  核对活动 A 的资格与提交要求
周四 19:30—20:30  整理活动 A 的作品说明
周六 10:00—11:00  参加活动 B（主办方固定时间）
```

以上完全为交互示例，不是用户实际日程；具体时段必须来自已录入的可用时间。导出 ICS 可保留，导出和通知送达是不同能力。

## 6. 页面与结构影响

| 当前部分 | 下一阶段变化 |
| --- | --- |
| Inbox | 单一收集框增加目标选择、图片上传、采集进度与补全入口 |
| Review | 可编辑字段、原文/图片证据、多个候选、冲突与未知条件 |
| Activities | 按目标呈现推荐顺序、参加理由、投入估计、待核验项，可比较与选定 |
| Brief | 逐步升级为本周计划，展示固定安排、准备任务、未排项与调整建议 |
| 用户偏好 | 区分跨目标的基础约束和每个目标的具体需求 |
| 评分服务 | 从固定类型加分改成按目标、事实与约束生成可解释评估 |
| 日历服务 | 保留 ICS；增加内部时间块与排期验证，外部日历连接暂后置 |

继续复用现有采集、草稿、活动、来源关联及数据库结构；不为讨论稿立即迁移数据库。实现前再确定最小增量模型：目标关联、按目标保存的评估、准备任务、可用时段与固定安排、计划版本与时间块。

评估至少要能识别机会内容、目标或个人约束是否变更，避免永远返回旧评分。建议在服务边界分开“事实抽取”“机会评估”“任务拆分”“时间安排”，保持错误可定位、结果可重算。

## 7. 实施顺序与验收

| 阶段 | 范围 | verify |
| --- | --- | --- |
| 1. 可信基础 | 修复微信 URL、日期、证据串用、Review 编辑、状态与 Brief 数据问题 | 跨年/非法日期/修正证据/不同活动证据隔离/正向抓取与失败降级定向回归 |
| 2. 三类入口 | 文本与图像统一抽取；微信/小红书只读适配器；多活动候选和补全路径 | 用户提供的三类样本均能生成有证据的候选，或清楚说明失败与补全方式 |
| 3. 按目标筛选 | 目标选择、约束检查、解释排序、人工调整 | 同一活动在两个不同目标下的理由和顺序可解释；未知条件不冒充已满足 |
| 4. 内部规划 | 手动忙闲、准备任务、容量检查、本周时间块、计划确认与重排 | 已知约束下不重叠、不超可用时段、依赖正确、截止前完成；排不下明确报出 |
| 5. 实际使用 | 用真实活动材料走完收集到执行，记录用户修改与完成反馈 | 比较原本笔记方式与系统的处理时间、纠错成本、计划修改和执行情况 |

每个阶段均可独立审查和回滚。首个完整演示应从用户提供的一批少量机会中，完成“按目标筛选 → 选定活动 → 录入笔记本已有安排 → 生成并确认周计划”。通过演示不等于已证明持续省时。

## 8. 尚待验证或以后决定

- 用户主要收集的实际链接形态、图像质量与典型活动跨度，尚需样本验证。
- 个人能力信息、目标模板、可用时间和预算尚未填写，不能生成真实个性化排序与日程。
- 准备任务耗时和活动收益属于估计，需要用户校正与使用反馈。
- 外部日历、到时通知、笔记本识别、公开信息主动搜索分别作为后续需求，不由当前讨论自动扩展实施。
- 本稿没有执行模型调用、读取第三方账户、安装适配器或改变线上系统。
