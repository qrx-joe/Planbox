## 目前还没定义的输入与边界

以下是需求材料的缺口，不表示用户做错了；其中有些可以通过设计默认值解决，有些必须由本人补充。

1. **目标的完成标准**：参加活动、交到朋友、完成可展示作品、获得奖励分别怎样判断？见 Q-001。
2. **资格与资源约束**：预算、城市、组队、能力边界和可用时间。见 Q-002/Q-003。
3. **跨目标冲突**：同一周两个高价值机会竞争时间时，优先保哪个？见 Q-008。
4. **信息变化**：赛程延期、截止修改、来源冲突、主办方取消后，怎样通知并重排？先保留来源版本，由用户确认关键变更；具体交互待定。
5. **不可逆操作**：报名、交材料、付款、联系主办方与队友不因“生成规划”自动获得授权，未来应有清楚的人为执行边界。
6. **计划失效**：临时有事、任务未完成、估时偏差时的处理，不能只设计第一次排期。见 Q-010。
7. **通知与保存**：用户是否需要到时提醒、导出、备份、删除原图和数据保留期限。见 Q-005/Q-009。
8. **截图信息缺失**：海报可能没有完整资格、报名地址或作品授权条款；需要跳转原始规则核实，不能靠模型补齐。

## 什么时候应调整方向

- 如果链接经常无法访问，优先优化截图/正文补全体验，而不是承诺全自动读取。
- 如果用户经常重排推荐，先检查目标和约束是否表达正确，再考虑更复杂模型。
- 如果计划总是超时，先校正工作量、缓冲与容量，再增加推荐活动。
- 如果主要负担是录入忙闲，再比较内部快捷录入、笔记识别与外部日历接入；不要预先同时实施。
- 如果系统比笔记本多花时间且没有帮助做取舍，先缩小闭环并重新验证价值。

评估记录模板：`观察到的事实 → 原假设 → 影响 → 首选调整 → 不利证据/剩余未知 → 复查条件`。建议变更必须附依据，不能把“用户使用过”自动解释成“用户满意或愿意付费”。
