# T-002 日期、时区与日历契约

日期：2026-10-18。以下是本项实现与验收契约；完成情况以 [T-002](to-do.md#t-002-时间数据和日历边界) 的实际测试记录为准。

## 表示与兼容

保留现有 `*_at: string | null` 与 `schedule` 字段，不迁移 SQLite，不重写历史记录。新增的 `time_issues` 为只读核对信息；草稿中的信息随既有抽取 JSON 保存，正式活动的核对信息从现有值计算，不另建存储列。

| 内容 | 示例 | 抽取/读取 | 新确认、时间修改与导出 |
| --- | --- | --- | --- |
| 带明确偏移的时刻 | `2026-10-20T09:00:00+08:00` 或 `2026-10-20T01:00:00Z` | 保留输入偏移；比较使用实际时刻 | 接受；ICS 转为 UTC，二者等价 |
| 只有日期 | `2026-10-20` | 保留 date 精度，不补 23:59 或午夜作为事实 | 接受；ICS 使用 `VALUE=DATE` |
| 缺时区的时间 | `2026-10-20T09:00:00` | 保留原值，标记待核对 | 要求补齐时区或明确改成日期，不能静默指定 UTC/上海 |
| 缺年或相对时间 | `1月5日`、`明天18:00` | 保留原值及可获得的发布/捕获参照，标记待核对；不猜年份或时区 | 核对前不作为可靠时间写入活动或日历 |
| 非法日期/时刻 | `2026-02-30`、`25:00` | 旧值与模型结果可读取并显示问题 | 拒绝；不自动滚动到下一月/日 |
| 未知 | `null` | 保持未知和缺失字段提示 | 可确认其他已知信息；无任何可导出节点时明确提示 |

精确时间接受 ISO 扩展形式（秒可省略，时区必须明确）；不接受时间戳数字、紧凑日期、周日期等未经项目定义的写法。`-00:00` 在 RFC 3339 中代表偏移未知，本项目要求核对后才能用于精确排期。

开始/结束都存在时，精度需一致，按实际时刻或日历日检查顺序。日期区间的结束日包含在活动中；精确区间结束必须晚于开始。局部 PATCH 要与已有值合并检查，不能只校验提交的一半。未知的结束时间不自动生成 30 分钟活动。

## 抽取与旧数据

- 规则抽取仅确定明确写出的日期/时间。缺年不使用运行当年；无时刻不补时刻；无时区不补 `+08:00`。未能确定的原始值留在草稿核对。
- 模型使用相同提示与运行时边界；提示词不能代替事实准确率评估。模型输出即使无法确认，也应让用户看到待核对原因。
- 有效的 `published_at` 优先作为参照，否则使用 `captured_at`，并记录参照种类；参照信息不自动将相对时间升级成确定日期。旧来源和原文仍保留。
- 旧活动可以读取；时间问题不会使列表整体读取失败。新确认和实际时间修改要先通过校验；与时间无关的编辑不批量修复旧值。已有误补时刻无法仅凭值辨认，不在本项猜测回填。

## 查询与展示

精确时刻按 UTC 等价关系筛选和排序，不能比较不同偏移的原始字符串。只有日期的条目按配置展示时区的日历日筛选；精确查询边界覆盖到的日历日包含 date 条目，这是粗粒度筛选约定，不表示截止时刻已知。日期查询的 before/after 包含该日。

排序时，日期条目按该展示日的起点排列，仅用作排序键，不改变保存值或声明实际时刻。无法解析的旧时间不参与时间区间筛选并排在合法时间后，读取时仍提供核对信息。前端将仅日期按日历日显示，避免把当天仅日期截止在当天午夜后提前判成过期；待核对时间不参与精确倒计时。

## ICS 与错误

- 日期使用 `DTSTART;VALUE=DATE`。含结束日的 date 区间转换成排他 `DTEND`；这个协议转换不改变源活动的包含式结束日。
- 精确时刻导出 UTC。结束未知则省略 `DTEND`；仅有结束节点时作为“结束”时间点导出。
- 遇到未核对的已知时间、错误区间或没有可导出时间的活动，返回可读的 409 核对清单（活动 ID、字段与原因），整次导出不生成残缺文件，不静默漏项。正确数据仍返回原有 ICS 下载。
- 使用 CRLF、文本转义、稳定 UID；超过 75 octets 的行按 UTF-8 字符边界折叠。这里只验证文件契约，不声称真实客户端已导入或收到提醒。

协议依据：[RFC 3339](https://www.rfc-editor.org/rfc/rfc3339.html#section-4.3)、[RFC 5545 内容行](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.1)、[VEVENT](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.6.1)。
