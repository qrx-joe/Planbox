## 当前目标

用户提供微信链接、小红书链接或图片，在收集时选择目标；系统提取活动与比赛、解释筛选排序，再依据用户录入的已有安排和可用时间，提出具体时段的计划。用户当前使用纸质小笔记本，没有固定数字日历。

“先做内部时间表、手动录入忙闲”是 AI 提出的首版建议，尚不等于用户对完整交互与架构的批准。用户已授权本轮生成规划、协作文档与技术规范，并分步骤做本地 Git 提交。

## 工作流与状态

任务状态：`todo`（未开始）、`doing`（进行中）、`blocked`（记录具体阻碍）、`done`（验收完成）、`deferred`（明确后置）。当前任务以 AI 实施、用户验收协作为默认职责分工；重大产品取舍仍由用户决定。

每次推进：选择一项 → 阅读相关规则与代码 → 写明复现或完成标准 → 最小修改 → 定向验证 → 更新任务证据 → 只提交该项范围。

任务卡至少包含：编号、目标、修改边界、依赖、verify、风险/回滚、实际结果、提交。验证失败时不得标 done；无法验证时必须记录未覆盖范围。

## 本轮文档交付的三步提交

1. 产品方向、问题清单、当前与后续待办。
2. 用户与 AI 的协作摘要、建议、未知和遗漏输入。
3. 参考来源、工程规范、项目级执行规则与导航。

提交不会自动开始业务实现，也不表示已部署或推送远端。完成记录写入协作文档，具体提交身份以 Git 历史为准。
